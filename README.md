# Music Player (Backend & Frontend)

Репозиторий содержит исходный код кастомного музыкального приложения, использующего API YouTube Music (через парсинг InnerTube) и систему рекомендаций Last.fm.

---

##  Важные ограничения перед развертыванием

> **Внимание (Локация сервера):** Из-за текущих ограничений YouTube и особенностей сетевой фильтрации, для успешной работы парсинга API серверная часть должна разворачиваться либо на зарубежном хостинге (VPS), либо в среде с настроенным системным проксированием/средствами обхода DPI(таким как Zapret). В противном случае запросы к инфраструктуре Google будут блокироваться.
>
> **Статус воспроизведения (По состоянию на июнь 2026):** В связи с изменениями в политике безопасности Google, прямая трансляция аудио-дорожек (CDN) на сторонние плееры временно ограничена. Поиск и резолв треков работают в штатном режиме, однако непосредственное воспроизведение потока через встроенные медиа-движки (включая VLC/LibVLC) в данный момент требует обновления алгоритмов обхода сигнатур.

##  Архитектура и пошаговый запуск

Проект состоит из четырех основных компонентов: ПОТ-провайдер (Node.js), YTDlp-серверы авторизации (Python), основной бэкенд (ASP.NET Core) и десктопное приложение (WPF/C#).

### Шаг 1: Развертывание ПОТ-провайдера (bgutil-ytdlp-pot-provider)
Необходим для генерации `PO Token`, без которого YouTube блокирует запросы к стримингу.

1. откройте консоль из папки **dlp servers**", cклонируйте и перейдите в директорию сервера:
   ```bash
   git clone --single-branch --branch 1.3.1 https://github.com/Brainicism/bgutil-ytdlp-pot-provider.git
   cd bgutil-ytdlp-pot-provider/server/
   ```
2. Установите зависимости и скомпилируйте TypeScript:
   ```bash
   npm ci
   npx tsc
   ```
3. Запустите сервис:
   ```bash
   node build/main.js
   ```

### Шаг 2: Подготовка Firefox-профилей и Python-серверов
Для обхода лимитов требуется запустить **4 независимых экземпляра** YTDlp-сервера (2 с авторизованными аккаунтами Google, 2 без).

1. Создайте 4 чистых профиля в браузере Firefox. В двух из них выполните вход в аккаунты Google на странице YouTube.
2. Найдите файлы баз данных кук (`cookies.sqlite`) для каждого профиля. Обычно они расположены по пути:
   ```text
   C:\Users\<UserName>\AppData\Roaming\Mozilla\Firefox\Profiles\<Имя_Профиля>\cookies.sqlite
   ```
3. В скриптах инициализации серверов (например, `serverUnlog1.py` и т.д.) настройте конвертацию кук, передав путь к файлу вашей БД с куками в качестве первого аргумента:
   ```python
   Handler.convert_firefox_cookies(r'C:\Users\...\cookies.sqlite', second_arg)
   ```
4. Поочередно запустите все 4 экземпляра Python-серверов в консоли (на портах `8888-8891`):
    ```python
    python serverUnlog1.py
    python serverUnlog2.py
    python serverLog1.py
    python serverLog2.py
   ```

### Шаг 3: Запуск основного бэкенда (ASP.NET Core)
1. Откройте решение `backendxd.sln` в IDE (Visual Studio / Rider).
2. Восстановите все Nuget-зависимости (IDE сделает это автоматически при сборке).
3. Создайте файл `.env` в корневом каталоге бэкенда и заполните его актуальными ключами (см. раздел конфигурации).
4. Запустите проект. При успешном старте в браузере откроется веб-интерфейс **Swagger API**.

### Шаг 4: Запуск десктопного фронтенда (WPF)
1. Откройте решение фронтенда `Frontend.sln` в Visual Studio.
2. Восстановите Nuget-пакеты и нажмите кнопку **Пуск** (Зеленый треугольник) для компиляции и запуска WPF-лаунчера.

## Обслуживание базы данных

В папке `scripts/` находятся инструменты для резервного копирования и восстановления базы данных Neon Cloud. Они автоматически считывают строку подключения из файла `.env` проекта.

> **Примечание:** В системе должны быть установлены утилиты PostgreSQL (`pg_dump.exe` и `psql.exe`). По умолчанию они ищутся по пути `D:\PostgreSQL\18\bin\`.

### Ручной запуск

* **Создание бэкапа:** Создает дамп базы в формате `.sql` в директории `backups/` в корне репозитория с временной меткой в названии.
* **Восстановление базы:** Автоматически находит самый свежий файл бэкапа в папке `backups/`, очищает существующие данные в таблицах (через безопасный `TRUNCATE CASCADE`) и накатывает сохраненную структуру.

Команды для выполнения:

```powershell
cd scripts
.\backup.ps1

cd scripts
.\restore.ps1
```
## Автоматизация по расписанию (Windows)

```powershell
cd scripts
.\setup_schedule.ps1
```
После этого задача пропишется в Планировщике заданий Windows (Task Scheduler) на ночное время.


##  Проверка работоспособности

Чтобы убедиться, что вся цепочка серверов взаимодействует корректно:
1. Откройте запущенный фронтенд.
2. Введите название любого трека в строке поиска.
3. Если трек успешно отобразился в результатах, попробуйте его включить. Если в левом нижнем углу успешно прошли статусы **Поиск...** и **Резолв аудио** а в логах ASP.NET отобразился успешный резолв URL аудио-дорожки — **инфраструктура развернута правильно**.

##  Спецификация конфигурационного файла (`.env`)

Данные переменные среды считываются сервером ASP.NET при старте для обеспечения доступа к базе данных, механизмам авторизации и прокси-воркерам.

| Переменная | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| **DB_CONNECTION_STRING** | Строка подключения к базе данных PostgreSQL (Neon Cloud) с поддержкой SSL. | `Host=ep-dark-king-anl9c26e-pooler...` |
| **JWT_KEY** | Секретный ключ (минимум 32 символа) для подписи токенов сессий пользователей. | `your_secret_key` |
| **MAIL_SENDER** | Email-адрес (обязательно mail.ru) для отправки системных уведомлений и кодов авторизации. | `yourMail@mail.ru` |
| **MAIL_APP_KEY** | Пароль приложения (App Password) для SMTP-сервера почтового провайдера. | `your_app_key` |
| **LASTFM_API_KEY** | Токен интеграции с API Last.fm для подгрузки музыкальных рекомендаций. | `LastFM_API_key` |
| **WORKER_URL2** | Адрес удаленного бэкенд-воркера на хостинге Render. | `https://render-worker-url.onrender.com` |
| **DLP_SERVER_UNLOG1_URL** | Локальный Python-прокси #1 для неавторизованных запросов YouTube. | `http://server_address:port1` |
| **DLP_SERVER_UNLOG2_URL** | Локальный Python-прокси #2 для неавторизованных запросов YouTube. | `http://server_address:port2` |
| **DLP_SERVER_LOG1_URL** | Локальный Python-прокси #3 с авторизованной сессией Google. | `http://server_address:port3` |
| **DLP_SERVER_LOG2_URL** | Локальный Python-прокси #4 с авторизованной сессией Google. | `http://server_address:port4` |
| **BASE_ADDRESS** | Базовый локальный адрес развертывания веб-сервера API. | `https://localhost:port/` |
